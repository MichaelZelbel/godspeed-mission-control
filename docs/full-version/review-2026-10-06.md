# Code review and fix wave, 6 to 7 October 2026

Reviewed `codex/godspeed-v2-completeness` at `c7d7dab` and the Windows installer branch
`codex/godspeed-v2-native-integration` of kit-bootstrap at `8833d1b`. Seven reviewers covered
storage, sync, the HTTP server and its trust boundaries, domain logic, the query layer,
background jobs and the runtime, and installation and deployment. Every finding below was
reproduced against the real modules on throwaway workspaces unless it says "from reading".
Each fix has a regression test that failed on `c7d7dab` and passes now.

## What was wrong, and is fixed

**Data integrity (storage, sync).**
- A save that failed part-way stayed prepared and was replayed by the next program to open the
  workspace, over newer edits, with no history copy. Failed saves now roll back; recovery replays
  only a transaction whose files are still as it found or left them, in preparation order, and
  sets any other aside for review.
- Taking over a dead writer's lock was not atomic: two programs could write at once.
- The server's watching store overwrote an outside edit (Obsidian, an assistant editing the file)
  without a conflict or history copy.
- A collection named "Secrets" or "node_modules", or a page saved with a byte order mark, could
  stop the workspace from opening or drop a record.
- The backup held the writer lock for minutes on a large notebook; failed backups left partial
  copies forever; restore wrote into the backup.
- In folder mode a merge was applied without validation, so one deleted page plus a new link to
  it stopped every save on every machine while sync said "synced". Edits to different fields of
  one note never merged. The mass-removal guard counted history files. A refused push left a
  merge commit that the owner's `git pull --rebase` then stopped on. Ignored pages and line-ending
  conversion silently diverged machines.

**Privacy and security (server, domain).**
- The assistant's generic `save_record` could rewrite the records that restrict it (privacy
  preferences, approvals, shares, agent instructions). It now writes an allow-list of tables, and
  the guard refuses control tables on every assistant path.
- Private-section facts, private groups and their briefings reached models through chat context,
  note processing, routine context and MCP reads. One rule in `visibleRows` now decides for all.
- A notes-only key read health, World, journal and coaching files. Watches and connectors could be
  pointed at internal addresses (`core/outbound-fetch.mjs`). A stranger's failed sign-ins locked
  the owner out. A media pairing key opened the whole API. One-time login links were spent by link
  previews. A trashed shared note stayed public. Errors showed server paths.
- Uploads with long or German names crashed the server process.

**Correctness (domain, query, jobs).**
- An AI edit of a long note saved the cut prompt copy as the whole note. Note chat overwrote owner
  edits made meanwhile. Changing a hidden fact's value un-hid it. Roll Back and Keep left facts or
  review items in wrong states. Partial application of conversation operations left work half done.
- The local query layer differed from Postgres in LIKE, `or()` quoting, embedded filters, NULL
  comparisons, ordering and paging, so notes search missed every multi-line note, People dropped
  contacts and duplicate people were created.
- The supervisor killed any routine or AI call longer than about four minutes, and gave up for
  good after five restarts. Every PC was called "local", so two PCs both ran the routines. An AI
  program that exited early crashed the server. Receipts and history grew by thousands of files a
  day. Meaning search broke silently when the embedding size changed.

**Installation.**
- A first Windows install with no repository address crashed under PowerShell 5.1 and the wizard
  still said "Finished" (kit-bootstrap `39d9142`). It now completes, reports a failed setup, refuses
  an update it cannot stop, and stops the notebook on uninstall.
- The Linux installer never restarted the notebook on upgrade, used a user service that stopped at
  logout, never checked the Node.js version, cloned 346 MB, renamed a server called "production"
  to "local" on a re-run, and ran the moving branch. A CI job now installs, upgrades and kills the
  notebook on a fresh Ubuntu (`notebook/test/native-install-linux.sh`).
- The image ran without an init, so finished programs piled up as zombies; the tool-using gateway
  received the web sign-in code; the setup code could be guessable and travelled in a URL.

## Verification

- Full notebook suite on Windows: 725 tests, 711 pass, 13 skipped (bash, POSIX signals or FFmpeg
  absent). The one failure, "actual file indexing leaves static and authentication requests
  responsive", is timing under parallel test load: alone it passes three of three on this code, as
  fast as on `c7d7dab`.
- CI on GitHub: the Linux install, upgrade and kill test, and the image build with the whole suite
  inside the container.
- Michael's real notebook (16,528 records), copied: opens with 0 problems on old and new code in the
  same time; its repository's line-ending rule passes the new check; no notebook page is hidden by
  its ignore rules.

## Still open

- **Published installers.** The fixes reach readers and Michael's machines only with a new
  `GodspeedSetup.exe`, a new release `install-godspeed.sh`, a new image pin in the Hostinger
  Compose files and README, and a redeployed Hostinger coordinator on the test server.
- **Product decisions.** Hermes routines live in each machine's Hermes and do not move when the
  routine owner changes. The record-based scheduler and planner run only in tests; shipped installs
  use Hermes.
- **kit-bootstrap.** The starter folder and tools are cloned from `main`, unpinned. A root Linux
  install still runs the notebook and its assistant as root. The vendored Hermes Windows installer
  downloads a moving Node.js and an unhashed PortableGit. Windows has no downgrade path, and the
  notebook still starts in whatever context runs setup (an elevated or remote one included).
- **Smaller.** Two PCs that both claim the old "local" owner before syncing run routines until the
  settings conflict is resolved. On Windows a dead writer's PID reused by another program without a
  reboot still blocks the lock. The owner and an attacker behind one address share a sign-in limit.
  The Hostinger link expires an hour after it was made if Hostinger fetches it later (the real flow
  is proven only by the `hostinger-automatic` job). When the editor's save times out, note chat
  sends no version (a UI change). Old media names over 181 characters do not sync. CI actions are
  pinned by tag, not commit.

## Second wave, 7 October 2026

The 18 fixes above were merged into `codex/godspeed-v2-completeness` (`b4d37c3`). The deferred
findings were then taken up on `review/v2-deferred-2026-10-07`, one fix per commit, each with a
regression test that fails on the code before it and passes after (shown for every one). Sync
suites were run one file at a time, at below-normal priority, after the live notebook on this PC
answered its health check quickly.

**Merging people.** A merge keeps one membership per group, one section per slug, one setting per
fact and one current value of a one-value fact; merging a merged person, or into one, is refused;
waiting suggestions follow the person. Merging a card into yourself carries its sections, and a
fact from a private section stays hidden. A person Menerio merged is as visible as the person they
went into. Removing someone from a group no longer brings them back as their duplicate. Keep works
on imported duplicate-person and relationship suggestions.

**Chats and note data.** A chat summary is read-only. Collection chat never saves the cut copy of a
long field, and "Rename" counts as a request. Note chat keeps a long note's tags and moves a note
to Trash instead of deleting it. Enrich and Classify take only visible, untrashed notes not done
yet, honour the person and the limit, and skip a failing note; finding people sends a bounded
batch. "Don't remind me" no longer makes a reminder. Notes from before automatic processing started
stay untouched after an edit.

**Sync.** A repository cloned into a synced folder, a link, or a name Windows cannot hold stays on
its machine and no longer stops sync. A push reported as failed keeps the merge's reviews. Settling
the review of a copied page never touches the original. Pruned receipts leave as removals. A note
edited in Obsidian during a merge keeps that edit. Settings written on two machines before they met
are kept for review. A stopped mass removal (system records now count) is one review that can keep
or accept it. A decided conflict holds while the other side's version is the one reviewed. A
moment's index lock no longer leaves the owner's index behind. The review screen can choose a
removal.

**Server and privacy.** What a key may read follows what a record is (facts need profile, contacts
or world; check-ins need actions). Meaning search sends nothing hidden or private to the embeddings
service. A damaged search index is rebuilt instead of stopping the start. A long Menerio import
keeps the heartbeat moving. A second supervisor steps aside. An assistant trashing a shared note
ends its public link. The notebook's pages may be framed only by the notebook, one unreadable
conflict file no longer takes the status down, and MCP tool errors are told as the HTTP API tells
them.

### Still open after the second wave

- **The note editor's version** (UI2): it saves with the last version any screen read, and the
  30-second refresh pulls outside edits into that. It needs the editor to hold the version it
  edited from and pass it through `useUpdateNote` and the query shim, and a reload-or-merge prompt
  on a newer version; it was not changed without a browser test of the editor.
- **Mixed conversation requests** (DM7, second half): record changes are atomic, but a request that
  also writes add-on files can still half-apply, and a retry with a new request id repeats the
  record part.
- **A copied page in folder mode** (SY1): settling its review is now safe, but sync keeps stopping
  until the copy is deleted on the machine that made it; the review says so.
- **A name Windows cannot hold** committed by the owner's own Git in folder mode stops a Windows
  machine until it is renamed; the sync status names it.
- **Force push** (SY6) was not taken up: the finding gives no scenario to reproduce, and none of the paths read loses an edit.
- **Smaller, from the first list:** SV8, the rest of SV9 (setup-code check, Range requests for
  video), UI5 to UI7, UI9, UI10, DP6 to DP10, JB8.
- **This PC's live notebook** (old code) answered its health check in 12 to 15 seconds for about a
  minute at a time, several times on 7 October, also with no test running.
