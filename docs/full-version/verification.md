# Candidate verification

This report describes verified synthetic outcomes, not a completed live rollout. Test fixtures contain no maintainer data or credentials. The capability matrix lists all 18 screens, 65 domains, 44 observed processing functions, 40 personal schedules and 61 recipes. Three generic TypeScript function calls were added when the actual group screens revealed them.

The automated runtime suite verifies durable CRUD, Unicode and external file edits, stable identities and aliases, typed references, multi-file crash recovery, stale write conflicts, case-folding, missing references, append-only timeline corrections, dated claims and cardinality, complete world relationships, collection schemas and linked rows, idempotent imports, review application/rejection/rollback, note conversation edits, media integrity, pairing, one owner, protected HTTP, one-time login, API scope and hidden-source privacy, uncertain Telegram sends, local account-reader fixtures, disk-full refusal and backup restoration. Tests use actual files, real HTTP, actual bare Git remotes and two offline workspaces. Model/provider failures remain failures.

Native assistant conversation state is also file-authoritative. An actual pinned Hermes SessionDB retained its session and exact message ID after deletion of state.db, then accepted another message. Independent Python/SQLite processes verify sequence high-water marks, Unicode and binary values, concurrent writers, immutable history, failed publication rollback, retained same-file conflicts and recovery after killing the Python writer between file publication and SQLite commit. Credentials and default assistant profiles are not read by these fixtures. See assistant-state.md for the contract and the whole-snapshot alpha performance limit.

Actual UI walkthrough on the shared Windows service created and edited a note, person, self-profile fact, world place/fact, collection schema and row, timeline event, group and membership, and action. It accepted a pending review proposal and scanned the media library. It generated an actual model weekly review and group briefing from synthetic sources. Collection sort preferences survived a full browser reload and were read back from a durable settings record. The walkthrough found and repaired ID/slug lookup, group defaults/join shapes, media batch preview, media response contracts, a model's string-valued review gap and the activity view. Activity derives from stable record history rather than a second mutable audit store. Favorites and file search are covered in domain fixtures. Every screen action has not been exercised against every possible imported legacy record; this remains an alpha trial limitation.

Real model fixtures used synthetic content and free OpenRouter models. A useful goal-work draft was saved and read back; image analysis read the supplied artificial receipt, including EUR 12.00. A native installed Hermes CLI, using an isolated test home, produced an actual conversation draft. A throttled free-model request was recorded as failed before using a different free model. HTTP endpoint/provider names alone are not counted as verified inference.

The Windows large-data fixture preserved 5,000 synthetic Unicode notes through restart, rebuild, backup and restore. Observed scan was 1.32 seconds, index rebuild 1.31 seconds and search 0.54 milliseconds on this computer; these are measurements, not a universal performance guarantee. Writes and restoration are journaled. Background fallback scan is every 30 seconds, with debounced file-change rebuild, to avoid continuous full scans at this size.

The VPS image has been built and booted in isolated local Docker/WSL storage. The bundled `notebook/scripts/verify-vps.py` exercises the actual extracted package, pinned image, HTTPS, separate volumes/ports, restart, index loss, compatible rollback/upgrade and checked restoration including media bytes. Windows installer has been compiled; native script fresh/upgrade checks ran with temporary account paths. The executable clean-account test runs on a disposable Windows runner and includes Hermes desktop provisioning, restart, offline retention, upgrade backup and uninstall retention. Final installer and VPS evidence, hashes and source pins are delivered with the artifacts; a successful run is required before declaring clean installation passed.

Limitations: the Lexicon was retired on 8 October 2026; the note graph is worked out from the notes when opened. Optional email/calendar, Drive, balance/board/posting, phone/video providers and external assistant accounts need the owner's own configuration. Posting adapters require an exact current approval and a returned receipt. Candidate Telegram and computer connection have fixture coverage and included source; no live test bot or Michael's browser has been paired. The Windows assistant does not install or upgrade shared system packages. Optional native video/voice recipes need ffmpeg when the chosen toolkit requires it; notebook media storage and endpoint analysis remain available. PDF processing requires a document-capable endpoint; native Hermes image mode does not claim PDF support. Reused cloud staff, billing and platform account screens are replaced by local ownership/configuration. Portable recipes omit private incident prose and separately owned company installations. No existing live data has been migrated or original source retired.
