# Opinion-leader work

Read the user's adopted public-lane plan, current strategy, positions, voice and approved/refused examples. These are workspace data, not a second copy of the method. Missing goals or exemplars remain missing. Do not transplant another person's positions, contacts, audience counts, private anecdotes or company duties.

One reusable method, one recurring trigger, many position/person data records and one output gate. Adding a position or contact never creates another skill or schedule. At most one actionable queue entry reaches the user per local day; zero is a logged result. The user publishes and sends. A draft, a checked draft and an actual posted result are different states.

The installed `/lead position` command links each adopted public position to its actual adopted goal using `goal_id`. Select the existing goal and position IDs from the notebook or command results; never guess them. An unrelated adopted goal does not activate public work. Pausing the linked goal stops drafting, and changing that goal or position during a draft prevents delivery until it is reviewed again. `/lead help` gives the installed configuration and outcome arguments. In Settings, Sources to watch, select sources for contributions explicitly and enable the Lead routine separately.

## Read actual outcomes before drafting

Read the last fourteen days of actual shown, answered, refused, ignored and posted contributions, grouped by kind, position and shape. Retain the denominator, dates and evidence. Do not infer a post from a draft or read a missing counter as zero. Quote the outcome summary in the run log.

If at least five open post entries exist and none was actually posted in fourteen days, add no new entry: redraft the best open one against approved examples and retain the superseded version. A shape shown four times with none posted is closed for that position until a new approved example supplies contrary evidence. Mine new refusals and user rewrites into the examples before writing again. Actual acceptance is the quality signal; a gate score does not override refusal.

## Look before choosing

Read the configured public profile and actual posted URLs, not only a scheduling service. Manual posts count when their real links and dates are established. Read whole host posts and their replies. Retain reaction/comment/impression counts as observed, with date and URL. Record a substantive argument with a position as an engagement event, and someone independently repeating the idea as a citation, quoting what they actually said. A reply worth answering can be today's move.

Check adopted positions due for another useful contribution. Check dated research steps: a due or overdue measurement step outranks a content idea. Complete it only after actual evidence or the user's confirmation; retain a missed step rather than silently moving its date.

When configured, read a rotating slice of fifteen target contacts plus every currently flagged contact, and a rotating slice of a market list. Advance by fifteen per day and wrap using dates and list length. For each inspected person retain their actual latest statement, URL, date, possible opening and fitting offer. A file existing is not evidence that the source was read. Correct a wrong URL while preserving the record. Prefer reachable people already asking a relevant question over famous cold contacts. Never invent a contact. A name from the user's life requires a confirmed relationship and an actual shared event, not a thin machine inference.

Use `/lead market` to select a public market source and `/lead markets` to inspect the saved list. Contacts and market sources have separate daily cursors; quiet days retain the sources actually read. `/lead contact` can retain an explicitly confirmed personal relationship and selected shared-event note. A named contact draft must quote a recent ISO-dated statement from that person's actual source and a useful offer from selected original-work evidence. Missing dates or evidence produce no named draft. A contact draft stays inside the day's single contribution and is never sent automatically.

## Make the contribution useful to strangers

Select the configured deliverable shape. The maintained compact post format is one queue entry containing three copy-ready single-sentence options, each under thirty words, at least one lighthearted, none opening with a count, plus optional one-line first comments. Include one named reach only when an actual recent statement and useful offer support it; otherwise log why none is ready. These options remain one entry, not three daily deliveries. If the user configured another shape, follow that actual choice and preserve the daily cap.

Before filing each line, record who sees it, where, what they understand and feel immediately, what they take away, and whether it resembles spam or a favour requested. Read it aloud. A stranger should understand it without a second sentence or an unexplained technical term. A position can sit underneath a true story or observation; put detailed evidence with the position for replies. Do not lead with counts merely to prove research. Imitate the approved examples' plainness without copying the joke or inflating the story.

Available shapes:

- Original post: a true attributable story or current sourced observation, ready to copy.
- Repost: an angle the fully read host post did not take, at most two sentences under thirty words; no link, number or favour. Humour points at a situation or ourselves, never at the author or people described.
- Comment: the casual, brief thought the room already understands. Inspect the room before the topic; retain actual host reactions/comments. Do not amplify a thread whose purpose is somebody's unrelated sales pitch.
- Reach: a real person, why them, a dated recent statement with link, and a draft offering one useful thing they can use today. No unsupported deadline/result promises, no suggestion that their product is broken, no request for a famous person's favour.
- Video: disabled unless the user confirms the production pipeline works. When enabled, prepare the script in its configured idea queue rather than assigning a recording task the user asked the system to remove.

Check every claim's actual author and credits. A maintainer thanking somebody else is not the user's achievement. Never smooth a small true event into a large invented success. Do not use confidential employer/client names. Do not put private-server or opaque internal links into social text. Read and apply the actual shared voice file; mechanical checks are a floor, not proof of reader acceptance.

## File, log and learn

Use the notebook's documented record or personal-operation tools after inspecting their schema. Retain kind, shape, position, source IDs/URLs, what it is, why it matters, next user action, complete draft, review evidence, actual state and stable request ID. A retry reuses the request; retain superseded versions. If the configured posting workspace has an authorized draft adapter, verify the ready text and required visual there. Missing adapters are implementation gaps, not successful delivery. A notebook draft is still a draft.

The briefing must show the complete ready text and one usable link, not a repository path or command for the user to execute. Sending, posting and scheduling external publication require the user's actual authorization. Never invoke publication merely to prove this recipe works. The queue and morning note are the delivery route; do not send an additional status message.

Every attempted run retains a dated log, including no finding and failure, with the outcome summary, actual sources read, chosen entry or reason, and next due time. An unchanged repeat does not create another entry or notification. A failed run without a log must not resemble a quiet successful run.

If the user has adopted a separate weekly comparison with a company, read its actual agreed protocol. Preserve the company's outputs verbatim; never produce them yourself. Retain and commit the blind key before any approved comparison page publication, record missing-side results honestly, and keep checking for late output until the agreed cutoff. This optional adopted duty is distinct from the daily entry and is not automatically enabled.

On the first configured monthly run, remeasure the user's adopted progress rungs against actual searches and posted evidence. An inaccessible rung is UNVERIFIED, never zero. Read citations without requiring the user's name to accompany the repeated idea. Retain the previous measurement rather than replacing it.

## Verify the actual result

Read back the saved entry, source quotes, run log and actual current state. Check the daily cap, blocked shapes, backlog/redraft rule, author attribution, links, voice, intended reader and usable delivery destination. Later actual acceptance/refusal/posting feeds the next run. No claim that the user posted or a rung moved without its actual evidence.


## Installed personal workspace

Use the current user workspace and its configured providers. Keep original workflow, command contracts, scripts and verification criteria. Read the workspace authorization rules before sends, sign-ins, payments or publishing. Search existing device-private credentials before asking for configuration. Saved output and a passing screen are not evidence that the full requested result happened.
