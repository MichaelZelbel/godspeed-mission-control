# Match an installed mission control to this companion kit

These are instructions for the assistant carrying out a request to match an installed mission control to this kit. The installers supply the programs and the current public starter. This guide brings an existing mission control's shared instructions into agreement with this kit's `starter-godspeed/`; it is not a replacement installer.

1. Confirm the mission control's path (normally `~/godspeed`, `C:\Users\<you>\godspeed` or `/home/ai/godspeed`). Read its `AGENTS.md` and `rules/`, and the kit's `starter-godspeed/AGENTS.md` and `starter-godspeed/rules/`. Save a local recovery copy of every file you will change, for example as a Git commit, and upload nothing.
2. Leave the persona block alone. If `AGENTS.md` has a paragraph between `<!-- persona:begin` and `persona:end -->`, keep it exactly as it is: it holds the name and character the user chose. If there is none, copy the kit's block, markers included, to the top of the file.
3. Merge the kit's shared instructions from `AGENTS.md`, outside the persona and rules blocks: finding and checking skills, the morning brief, saving useful updates during the conversation, what stays in `inbox/` and keeping filed originals in `archives/filed-captures/`, keeping current notes current, keeping practice material separate, adding projects to `dev/`, `goals/`, `forecasts/` and `work/`, the life record in `world/` (which works without Menerio), targets and deadlines through `mc-due`, `mc-search`, the note and email recipes, and uploading only after the user approves a private remote. Where the user's own instructions already answer a question, keep their choice. Never bring in someone else's preferences as facts about the user.
4. Add what the starter has and this mission control lacks, without overwriting anything: the READMEs of `world/`, `due/`, `goals/`, `forecasts/`, `work/`, `ideas/`, `inbox/`, `dev/` and `prompts/`, the folders `world/entities/`, `world/events/` and `world/claims/`, and the recipes in `starter-godspeed/skills/`. Where a README or recipe already exists and differs, merge rather than replace it, and keep a recipe the user has changed. Preserve every record, origin marker and dated history.
5. Compare `rules/` with the kit's rule files and bring in the kit's clarifications, for example that a clear request to edit a file authorises that edit while a general tidy-up does not permit deleting unrelated material. Keep stronger limits and exceptions the user added. Then run `mc-compile-rules` and check the generated block; never edit the block by hand. If the program is missing, diagnose that installation step instead.
6. Check the installed assistant's allowance for instruction files. Keep `AGENTS.md` below the smaller of that allowance and 19,000 characters, moving examples into reference files if needed while keeping every behaviour instruction. Check that every file it points to exists.
7. Check the optional conversation-collection and notebook-copying jobs, including a notebook post-commit hook if present. For a first setup both stay off: disable only these kit jobs and keep other schedules and custom hooks. Report any service already connected, without printing credentials or widening its access.
8. Report which instructions changed, what stayed personal, whether the compiled rules are current, and any step you could not verify. Do not create schedules, connect a service or upload files.

On a server, follow the same steps after the server installer finishes. Keep the server's paths and working connections, and do not copy desktop-only settings into them.
