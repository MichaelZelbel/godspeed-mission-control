# The names JavaScript gives to every object it builds. A stage file names none of them, and
# neither reader may answer about one: not as a field the file holds, and not as a field asked
# for. stage/test-stage.mjs, stage/test-stage-sh.sh and stage/test-stage-agree.sh all sweep this
# one list, so a name added here is swept by all three. One name a line; a # line is a comment.
#
# Why they are a trap for the Node reader: JSON.parse builds plain objects, every plain object
# inherits these names from Object.prototype, and a bare lookup finds an inherited name as readily
# as one the file wrote. __proto__ is worse than the rest - JSON.parse makes it an own field - so a
# stage file can really carry one.
# And why they are a rule for both readers, not a Node repair: where the schema names an add-on or
# a server edition by a pattern, a stage file names its own fields, and a lowercase inherited name
# is one that pattern matches - own fields or not, both readers would read an add-on called
# constructor. So stage.schema.json writes this list down under neverNamedFields, stage/stage.mjs
# reads it from there and stage/stage.sh repeats it, and the three tests put every name here in six
# places with a value no rule can object to, so the refusal can only be about the name.
toString
constructor
__proto__
hasOwnProperty
valueOf
isPrototypeOf
propertyIsEnumerable
toLocaleString
__defineGetter__
__defineSetter__
__lookupGetter__
__lookupSetter__
